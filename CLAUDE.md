# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Otso's personal NixOS configuration for the host `markeeg`, managed as a flake with home-manager. This is a live system config — edits here will be applied to the running machine. Expect ongoing customization: new packages, new services, new home-manager tweaks. Treat each change as a small, reviewable diff to a working system, not a greenfield project.

## Commands

```bash
# Apply changes to the running system (the canonical workflow).
asenna                                              # alias for the line below
sudo nixos-rebuild switch --flake ~/.dotfiles#markeeg

# Validate the configuration without activating it. Run this before suggesting
# `asenna` so we don't ask for sudo on a broken config.
nixos-rebuild build --flake ~/.dotfiles#markeeg
```

`nixos-rebuild build` produces a `./result` symlink but does not touch the system. It catches evaluation errors, missing options, and build failures — i.e. everything `switch` would catch, minus activation.

## Layout

The flake (`flake.nix`) wires together three files into a single `nixosConfigurations.markeeg`:

- **`configuration.nix`** — system scope. Bootloader, networking, locale, services (KDE Plasma 6, PipeWire, CUPS), system-wide packages, Firefox enterprise policies, default shell. Anything that must exist before login or that applies to all users goes here.
- **`hardware-configuration.nix`** — generated by `nixos-generate-config`. Do not hand-edit unless overriding hardware-specific behavior; regenerate after hardware changes.
- **`home.nix`** — user scope for `otso`, imported via the `home-manager.nixosModules.home-manager` module. User packages, dotfile-style program config (git, fish, firefox profile), shell aliases.

### Where to put a new package

- **System-wide CLI or service** (e.g. `git`, `helix`, a daemon) → `environment.systemPackages` in `configuration.nix`.
- **Personal tool that only `otso` uses** (e.g. `ripgrep`, `fd`) → `home.packages` in `home.nix`. Prefer this by default — it keeps the system closure small and the config focused.
- **Program with managed config** (shell, editor, git) → use the `programs.<name>` module in `home.nix` rather than installing the bare package, so config and binary stay together.

## Conventions

- `nixpkgs` tracks `nixos-unstable`; `home-manager` follows the same nixpkgs (`inputs.nixpkgs.follows = "nixpkgs"`) to avoid version drift. Keep it that way when adding inputs.
- `nixpkgs.config.allowUnfree = true` is set, so unfree packages are fair game.
- Locale is `en_NZ.UTF-8`, timezone `Pacific/Auckland`.
- Default shell is fish (set in both `configuration.nix` for the user account and `home.nix` for program config).
- After changing inputs in `flake.nix`, run `nix flake update` (or `nix flake lock --update-input <name>`) to refresh `flake.lock`; commit the lockfile alongside the change.
