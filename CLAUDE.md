# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Otso's personal NixOS configuration for the host `markeeg`, managed as a flake with home-manager. This is a live system config — edits here will be applied to the running machine. Expect ongoing customization: new packages, new services, new home-manager tweaks. Treat each change as a small, reviewable diff to a working system, not a greenfield project.

## Validating packages and config

Always validate against this flake's pinned `nixos-unstable`, not a generic web search — a stable-channel option may not exist on unstable, and vice versa.

**Is the package available, and what's it called?**

- `nix search nixpkgs <term>` — searches the flake's pinned nixpkgs, so results match what `nixos-rebuild` will resolve. Best first stop.
- https://search.nixos.org/packages — same data via web UI. Set the channel selector to **nixos-unstable**.
- `nix repl` → `:lf .` → tab-complete `pkgs.` — confirms an attribute path resolves before you edit a `.nix` file.
- `nix-locate <binary>` (from `nix-index`) — reverse lookup ("which package provides `rg`?") if you only know the executable name.

**How is the option spelled / what does it accept?**

- https://search.nixos.org/options — authoritative for NixOS module options (`services.*`, `programs.*`, etc.). Switch channel to **nixos-unstable**.
- https://nix-community.github.io/home-manager/options.xhtml — separate namespace for anything inside `home.nix`. Don't confuse the two.
- When docs are thin, read the module source directly on the `nixos-unstable` branch of https://github.com/NixOS/nixpkgs, or `:e <nixpkgs>/nixos/modules/...` from `nix repl`. Option descriptions, defaults, and the generated config live there.
- Renamed/removed options after a `nix flake update`: skim https://nixos.org/manual/nixos/unstable/release-notes.

**Verify before activating.**

- `nixos-rebuild build --flake ~/.dotfiles#markeeg` is the cheap feedback loop — catches typos, missing options, type mismatches, build failures. Run it before suggesting `asenna`.
- `nix eval .#nixosConfigurations.markeeg.config.<path>` spot-checks that an option is wired the way you think (e.g. `...config.services.printing.enable`).

## Layout

The flake (`flake.nix`) wires several modules into `nixosConfigurations.markeeg`. Each `.nix` file owns one concern — when adding system-scope config, drop it into the module whose purpose matches, or create a new module if no existing one fits.

- **`configuration.nix`** — host-level glue and the entry that imports the rest. Bootloader, hostname, NetworkManager + declarative WiFi profile, locale/timezone, PipeWire, CUPS, fwupd, Bluetooth, Steam, sleep-disable, Nix store maintenance (GC, auto-optimise, channels off), default shell, system-wide CLI packages.
- **`vpn.nix`** — NordVPN over native WireGuard (NordLynx), the `vpn-hop` country switcher, the nftables kill-switch, and `systemd-resolved` (paired here because wg-quick's `dns =` push needs it).
- **`desktop.nix`** — graphical session: keyd input rewrites, Hyprland under UWSM, xdg.portal wiring, greetd/tuigreet login.
- **`fonts.nix`** — system font set and the fontconfig fallback chain.
- **`firefox.nix`** — Firefox enterprise policies (telemetry/ML/promo prefs locked, extension force-installs, content blocking).
- **`hardware-configuration.nix`** — generated by `nixos-generate-config`. Do not hand-edit unless overriding hardware-specific behavior; regenerate after hardware changes.
- **`home.nix`** — user scope for `otso`, imported via the `home-manager.nixosModules.home-manager` module. User packages, dotfile-style program config (git, fish, kitty, helix, hyprland, hyprlock, hypridle, starship, peon-ping), shell aliases.

## Conventions

- `nixpkgs` tracks `nixos-unstable`; `home-manager` follows the same nixpkgs (`inputs.nixpkgs.follows = "nixpkgs"`) to avoid version drift. Keep it that way when adding inputs.
- `nixpkgs.config.allowUnfree = true` is set, so unfree packages are fair game.
- Default shell is fish (set in both `configuration.nix` for the user account and `home.nix` for program config).
- After changing inputs in `flake.nix`, run `nix flake update` (or `nix flake lock --update-input <name>`) to refresh `flake.lock`; commit the lockfile alongside the change.
- This host is flake-only. `nix.channel.enable = false` in `configuration.nix`, so `nix-channel --update` is intentionally broken — don't "fix" it. Ad-hoc commands like `nix shell nixpkgs#foo` resolve via `nix.registry.nixpkgs.flake = nixpkgs;` (set in `flake.nix`), so they hit the same locked revision as the system build.
- Flake evaluation only reads git-tracked files. A new `.nix` module won't be visible to `nixos-rebuild` until it's at least `git add`-ed (intent-to-add is enough; no commit required). The error names the missing file, so it's recoverable, but it's faster to add upfront.
